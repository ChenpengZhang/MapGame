# 前端架构与改动指南

> 本文档说明 `frontend/js/` 目录的分层结构，以及"以后要加功能/改参数时该动哪个文件"。
> 表内 `core/`、`game/` 等短路径均相对 `frontend/js/`；页面在 `frontend/index.html`。
> 仓库布局改变不影响公开 URL：服务器将 `frontend/` 映射到站点入口，`shared/` 和 `data/` 单独映射。
> 重构背景：`frontend/js/app.js` 原本 2287 行、把常量/状态/渲染/玩法/剧情/爬塔全塞在一起，
> 现在按依赖方向拆成 5 层、30 个文件，每个文件只做一件事。

## 1. 分层总览

依赖方向**只能从上往下**，禁止反向 import（`core` 是最底层）。

```
app.js                入口（组合根）：引导 + 组装 + 事件绑定
   │
   ├─ ui/             表现层：路线面板、结果弹窗、菜单、剧情对话框（只读 state + 纯函数）
   │
   ├─ game/           玩法层：路线规划、时间模型、会话/菜单流程、爬塔、结算
   │
   ├─ map/            地图渲染层：动画、站点图层、路线图层、步行
   │
   ├─ data/           数据层：关卡剧本、数据加载、站点索引
   │
   └─ core/           基础层：常量、全局状态、DOM 工具、事件总线、localStorage、寻路器适配

   shared/router.js       纯算法（Dijkstra 寻路器，UMD），不在分层里，被 core/router-api.js 引用
   frontend/js/amap-polyfill.js 免 Key 地图后端（Leaflet+OSM 模拟高德 API），提供全局 AMap
```

### 关键规则

1. **状态集中在 `core/state.js`**：`state.xxx` 是唯一跨模块可变状态。
   只被单个模块内部用的状态（如站点图层的显隐标记）留在那个模块内，别塞进 state。
2. **`ui/` 是"哑"的**：只渲染、只收回调，绝不 import `game/` 的流程模块
   （可以 import `game/time-model.js` 这种纯计算）。这样 `game → ui` 单向、无环。
3. **跨层通知只走 `core/bus.js`**：目前只有一个事件 `optimal:ready`
   （最优路线算完 → 谁结算由 `game/flow.js` 订阅决定）。
   它的作用是打破 `route → optimal → session/tower` 的循环依赖。
4. **事件绑定只在 `app.js`**：全项目唯一的 `addEventListener` 集中地，
   找"点这个按钮发生什么"直接看 `app.js` 的 `bindUiEvents()`。

### 样式表（`frontend/css/`）

原来内联在 `index.html` 的 `<style>` 已按原顺序拆成多个文件，`index.html` 按下列顺序引用，**顺序即层叠优先级，不要调换**：

| 文件 | 内容 |

| `base.css` | reset、`html/body`、`#app`、`#map` |
| `hud.css` | 顶栏、城市选择、图例、路线面板、信息卡、图钉、操作条、加载遮罩 |

## 3. 常见改动去哪改

- **调速度/换乘/等车/站点合并/起终点步行上限** → `shared/router.js` 的 `DEFAULT_PARAMS`；**配色和前端显示阈值** → `core/config.js`。
- **改剧情、关卡、教学文案、爬塔畸变** → `data/levels.js`。
- **加一个游戏模式** → `game/` 新建一个文件 + 在 `app.js` 绑按钮 + 菜单项在 `frontend/index.html` / `ui/menu.js`。
- **加一个地图图层** → `map/` 新建文件，图元复用 `stop-marks.js`、动画复用 `anim.js`。
- **加一个界面组件** → `ui/` 新建文件，只读 `state` + 纯函数，必要时收回调。
- **加一个跨层通知** → `core/bus.js` 登记事件名，emit 方与订阅方互不 import。

## 4. 为什么把"走路"做成直线估计而不是高德 API

见 `map/walk.js` 头部注释：最优点与玩家点必须用**同一套步行口径**，
否则会出现"系统最优比玩家还慢"（`test-optimal-invariant.js` 专门守这条不变式）。
高德真实步行路网的代码保留在 `map/walk.js` 第 2 段，标记为"当前未接入"。

## 5. 已知未动的事项（保持行为一致）

- `game/progress.js` 里 `DEV_DEBUG_MODE = true`：开发者调试开关，发布前应改回 `false`。
- `map/walk.js` 的高德步行、`map/map-init.js` 的 `isLeafletBackend()`、
  `state.logicalPhysMap` 等目前未被调用，属"保留备用"，未删除（避免改变行为）。
- `data/sample.json` 的站点没有站间距 `d`，导致在演示数据下寻路器算不出最优路线
  （只有步行可达）；全量 `beijing-transit.json` 有 `d`，不受影响。

## 6. 验证

- `node test/test-app-smoke.mjs` —— 无浏览器冒烟测试（模块图 + 主流程），默认 sample 数据；
  `MG_FULL=1 node test/test-app-smoke.mjs` 用全量数据跑一遍。
- `node test/test-router.js` / `test/test-integrity.js` / `test/test-optimal-invariant.js` —— 原有测试，不受影响。
- 浏览器人工验证：`node server.js` 后打开 http://localhost:8080。

## 账户与服务端结算

`core/api.js` 统一同源 `/mapgame/api` 请求、Cookie 和错误提示；`core/account.js` 保存当前会话状态。`game/account-actions.js` 负责登录、注册验证码、找回密码验证码、新密码设置和历史列表；所有账户步骤都在同一个最小化弹窗内互斥显示。

`game/online.js` 为登录用户向服务端申请题目，把完整站点路线序列化后提交。`ROUTE_FINISHED` 事件触发上传；在线模式不会使用本地 `OPTIMAL_READY` 结果判断通关。结算、通过层数和时间以服务端返回值为准：本地计时器从服务端的 `startedAt` 展示，每层结束再用服务端返回的本层和累计 `elapsed_ms` 校正。客户端不上传任何计时值。上传重试复用原请求 ID 和原路线，避免重复记账。地图数据哈希必须与服务器一致，演示数据不能提交账户记录。

游客沿用本地流程。账户爬塔进度从 API 读取，不导入游客缓存；登录成功后会清除各城市的游客无尽记录并重新载入页面，隔离账户与游客状态。服务端仅保存完成并验证的路线，不保存正在编辑的路线。无尽账户对局支持站间步行换乘，服务端按物理站连续性逐段复算。

## 测试命令

```bash
node test/test-router.js            # 寻路回归测试（故宫→国贸 正常/禁用地铁）
node test/test-integrity.js         # 数据完整性：逻辑站 id 唯一、物理站线路映射无缺失
node test/test-optimal-invariant.js # 不变式：系统最优 ≤ 玩家可达方案（防「最优比玩家慢」）
node test/test-app-smoke.mjs        # 前端冒烟测试（模块图 + 主流程，Node 桩环境，无需浏览器）
node --check shared/router.js
npm run test:paths               # 根路径、/mapgame/、静态产物与发行包资源
```

真实浏览器流程测试使用 `npm run test:e2e`，默认验证 `/mapgame/`。可用 `E2E_BASE_PATH=/` 切换为根路径，
用 `E2E_BROWSER=chrome` 选择已安装的 Chrome（默认 Edge）；需先 `npm ci` 安装 Playwright。

日常只需 `npm test`（前端与数据回归）和 `cd backend && npm test`（后端；设置 `TEST_DATABASE_URL` 时含 PostgreSQL 集成测试）。
